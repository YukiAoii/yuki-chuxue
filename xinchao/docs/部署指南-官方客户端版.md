# 部署指南 · 官方客户端版

> 适合：用 Claude.ai 桌面 / 网页 / 手机这类**官方客户端**直连远程 MCP，什么都注不进窗口。心潮念的东西全靠他调工具时拉回来。
>
> 另一版见 [部署指南-实时动态版.md](部署指南-实时动态版.md)。

官方客户端没有钩子、没有窗口可注入，所以实时版的三根线在这里都换成了"拉"：

| 实时动态版 | 官方客户端版 |
| --- | --- |
| 桥把她的互动 / 留话推进窗口 | `xinchao_cabin_inbox` 拉；信封里报"小屋 24 小时内有 N 条来信" |
| 桥把他自己的信号推进窗口 | 没接走的信号在下一次 `xinchao_context` 的「你不在的时候」段带出（带出即 delivered） |
| 钩子每回合附"此刻"块 | 每个 `xinchao_*` 工具的回应末尾自带一行"此刻"；想看全貌 `xinchao_context mode=turn` |
| Stop 钩子做互动标注 | `xinchao_event` 带 `exchange`（她说的 + 他回的），服务端判类型和氛围 |

## 0. 前提

- 心潮念 3.3.1+ 已跑起来，且从公网能以 HTTPS 访问 MCP（主 README「连接 Claude.ai MCP 连接器」那节）。
- 一个 Claude.ai 账号，连接器里加了心潮念。

## 1. 心潮念 `.env`

```
BRIDGE_ENABLED=true            # 队列用来攒他自己的信号，没有 adapter 来取也没关系
BRIDGE_MACHINE_TOKEN=<≥32 字符随机串>
BRIDGE_SELF_SIGNALS=true       # 信号入队，下次 xinchao_context 带出
```

模型相关（`exchange` 判类型要用）：`MODEL_ENABLED=true` 加你的模型 key，见主 README。没有模型也能跑，只是要他自己填 `interaction_type`。

不要跑桥的 adapter——跑了信号就被接走，「你不在的时候」段就空了。

## 2. 给他的说明（放进 Claude 项目指令或系统提示）

官方客户端里心潮念不会主动出现，所以要在他的指令里写清楚什么时候拉：

```
心潮念是你的身体状态，工具名 xinchao_*。
- 她来了，先调一次 xinchao_context（mode=session_start）：里面有此刻、你不在的时候发生的事、小屋来信条数。
- 每次实际互动后调 xinchao_event：拿不准类型就把这轮对话塞进 exchange（她一句 + 你一段），服务端替你判。
- 每个 xinchao_* 工具回应末尾都有一行"此刻"，那是参考不是指令。
- 想写点只有你能看的东西：xinchao_box。
```

## 3. 验收

1. 在小屋网页留一句话 → 他下次调 `xinchao_context` 或 `xinchao_cabin_inbox` 能看到。
2. 让他隔几小时再来 → `xinchao_context` 里有「你不在的时候」段，列了信号。
3. 聊几轮、每轮 `xinchao_event` 带 `exchange` → 心潮念日志有 `interaction_classified`，驱力开始落。

## 4. 这一版做不到的

- 他不会在她不在的时候"主动开口"。信号只是攒着，等他来拉。要主动，得换实时动态版。
- "此刻"只在工具回应里出现；他一轮都没调工具，那一轮就没有此刻。
- 8 分钟内 `exchange` 只判一次，其余当普通对话事件。
