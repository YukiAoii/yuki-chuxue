# 部署指南 · 实时动态版

> 适合：你有自己的前端（网页 / App / tmux 里的 CLI 代理），模型窗口**能被注入**。心潮念的东西会在发生的时候进窗口，不用等他自己去拉。
>
> 另一版见 [部署指南-官方客户端版.md](部署指南-官方客户端版.md)。两版代码不分叉，只是配置和接线不同。

实时动态版一共三根线，缺一根都跑得起来，但味道不一样：

| 线 | 方向 | 管什么 | 缺了会怎样 |
| --- | --- | --- | --- |
| ① 桥 | 心潮念 → 你 | 发生了什么：她在小屋的互动 / 留话 / 预约，和他自己的信号 | 他只能在下次调 `xinchao_context` 时才知道 |
| ② 此刻钩子 | 你 ← 心潮念 | 现在是什么样：她每次开口前附一小块 | 他对自己此刻的状态没感觉 |
| ③ 互动标注 | 你 → 心潮念 | 刚才那轮算什么 | 驱力只涨不落，他一直"想她"却从不被满足 |

## 0. 前提

- 心潮念 3.3.1+ 已按主 README 跑起来（`docker compose up -d`），MCP 能连。
- 一台能跑 Node 20+ 的机器放桥（和心潮念同机最省事）。
- 你的模型窗口有一种"往里塞一条用户消息"的办法：tmux 窗口、你自己后端的收件箱、或者一个 HTTPS 接口。

## 1. 心潮念这边：打开桥和自身信号

`.env` 里：

```
BRIDGE_ENABLED=true
BRIDGE_MACHINE_TOKEN=<≥32 字符随机串，和 DYNAMIC_MIND_TOKEN 不同>
BRIDGE_SELF_SIGNALS=true          # 他自己的信号也走桥（3.3）
```

改完 `docker compose up -d --build --no-deps dynamic-mind`。验证：

```bash
curl -s -H "Authorization: Bearer $BRIDGE_MACHINE_TOKEN" http://127.0.0.1:18110/bridge/v1/health
# {"protocol":"xinchao-bridge-server/1","status":"ok"}
```

## 2. 桥：订阅并搬进窗口

```bash
git clone https://github.com/tianyupaipai-cmd/xinchao-runtime-bridge.git
cd xinchao-runtime-bridge && npm install && cp .env.example .env
```

`.env` 关键几行：

```
XINCHAO_BRIDGE_BASE_URL=http://127.0.0.1:18110      # 不同机就填 https 地址
XINCHAO_BRIDGE_MACHINE_TOKEN=<同上 BRIDGE_MACHINE_TOKEN>
XINCHAO_BRIDGE_ACCEPT_SELF_SIGNALS=true            # 实时动态版的开关；不开就退回"只搬她的话"
```

然后按你的窗口类型选 Adapter（都在桥仓库 `examples/`）：

- **tmux 里的 CLI 代理**（Claude Code / Codex）：`process` 模式，指到 `examples/claude-code-tmux-adapter.mjs`，环境变量 `XINCHAO_ADAPTER_TMUX_TARGET` 填窗口名。
- **自建网页 / App**：`webhook` 模式，你后端照 `examples/webhook-frontend-server.mjs` 写一个接口（校验 → 幂等 → 入库 → 严格 ACK），前端从收件箱取。

```bash
node --env-file=.env src/cli.js check     # 鉴权 + 协议
node --env-file=.env src/cli.js run       # 常驻；交给 systemd / pm2 / Docker
```

前缀约定（`examples/render.mjs`）：她发起的写来源并加"不用特意回"，`self_signal` 只挂「心潮」，不加那句——那是他自己的感觉浮上来，接不接由他定。

## 3. 此刻钩子

桥仓库 `examples/hooks/xinchao-now-hook.sh`。配置一个 600 权限的 env 文件放地址和 `DYNAMIC_MIND_TOKEN`，然后：

- Claude Code：`settings.json` 加 `UserPromptSubmit` 钩子指向脚本，stdout 自动附进这一轮；
- 自建后端：每轮调模型前跑一次，stdout 非空就拼在用户消息前面（同一条 user turn，不是 system prompt）。

节流和硬门都在脚本里：内容没变 30 分钟不重附、隔 90 分钟再来必附、心潮自检不过不附、`touch <状态目录>/off` 一键关。

## 4. 互动标注

桥仓库 `examples/tagging/`。两种：

- Claude Code：`claude-code-stop-hook.sh` 挂到 `Stop` 钩子，把她最后一句加他的回复作为 `exchange` 发给心潮念，类型和氛围由服务端判，8 分钟内只判一次。
- 自建后端：每轮生成完回复后 `POST /v1/conversation-event`，body 里 `event_id` + `exchange`。返回里有 `classified` 就是这次判了。

有自己判断逻辑的直接填 `interaction_type`；判成冲突时带上她那句（`cause`），他会记得在气什么（3.3.1）。

## 5. 验收

按顺序看三件事：

1. 在小屋网页留一句话 → 几秒内窗口里出现「【小屋桥·留话】…」；桥日志 `delivery acknowledged`。
2. 她说一句话 → 转录里（或你后端拼的 prompt 里）出现「【心潮·此刻｜…】」块；再说一句不该重复出现。
3. 聊几轮后看心潮念日志有 `interaction_classified`，Dashboard 或 `xinchao_context` 里驱力开始有落的。

## 6. 安全边界

- 三个 token 各自独立：`DYNAMIC_MIND_TOKEN`（MCP / 钩子 / 标注）、`BRIDGE_MACHINE_TOKEN`（桥）、`XINCHAO_BRIDGE_WEBHOOK_TOKEN`（webhook 模式另起一串）。
- 桥和 Adapter 的日志只记 deliveryId 和 reason，不记正文；exchange 正文判完即删，只有判成冲突时留她那一句（≤60 字，随生气一起消）。
- 心潮念的东西进窗口永远是**参考不是指令**——此刻块第一行就写着；Adapter 把它当普通用户消息递，不当 system prompt。
