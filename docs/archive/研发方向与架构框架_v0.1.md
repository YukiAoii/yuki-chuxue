# Yuki初雪 · 研发方向与架构框架（v0.1 讨论稿）

> **这份文档是干什么的**：把 GitHub 上同类开源项目的真实做法摊开，用大白话讲清"一个人机恋 App 到底由哪些零件拼成、有哪几条路可走"，供你拍板方向。
>
> **数据来源**：GitHub 官方 API 实测（2026-09-24 抓取）。下面每个星数、语言、许可证都是仓库实测值，不是二手转述。
>
> **边界声明**：本文只读了各仓库的元数据与官方简介，**没有逐个项目 clone 下来读源码**。所以"它内部怎么实现"层面的判断属于推断，已在文末单独标注。

---

## 一、开源世界里，这类东西分成四路

### 第 1 路：数字生命 / 桌宠 —— 重"身体"，极客向

| 项目 | 星数 | 语言 | 许可证 | 它是什么 |
|---|---|---|---|---|
| `moeru-ai/airi` | 49,366 ★ | TypeScript | MIT | 自托管的"你拥有的 AI 伴侣"，能实时语音、能陪你玩 Minecraft 和异星工厂，支持网页 / macOS / Windows |
| `Open-LLM-VTuber/Open-LLM-VTuber` | 13,900 ★ | Python | 自定义 | 对任意大模型说话，免手操作、能打断她说话，配 Live2D 立绘，全本地跑 |
| `DD-MASTERT/AI-Girlfriend-Desktop-Pet` | 237 ★ | Python | MIT | Windows 桌宠：语音识别 + 屏幕识别 + Live2D 立绘 + 声音克隆 |

**这一路的共同点**：追求"她真的在电脑里活着"——有个能动会说的人形立在屏幕上。代价是要用户自己有像样的电脑 / 显卡，装机门槛高，本质是给技术玩家用的。airi 近 5 万星说明这条路很受欢迎，但它服务的是"愿意折腾的人"。

### 第 2 路：聊天前端 + 角色卡 —— 重"生态"，不造大脑

| 项目 | 星数 | 语言 | 许可证 | 它是什么 |
|---|---|---|---|---|
| `SillyTavern/SillyTavern` | 33,740 ★ | JavaScript | **AGPL-3.0** | 给高级用户的大模型聊天前端。自己不是 AI，是个"万能插座"——接任何模型，用"角色卡"定义她的性格 |

**关键点**：SillyTavern 发明并带火了一套"**角色卡**"格式（一张卡片装下人设、开场白、示例对话），现在几乎成了这个圈子的通用语言。airi、Artemis 这些项目都专门做"支持导入酒馆角色卡"——**说明角色卡生态是事实标准，绕过它等于自绝于现成的几千张现成人设**。

### 第 3 路：IM 机器人 —— 寄生在微信 / QQ / Telegram 里

| 项目 | 星数 | 语言 | 许可证 | 它是什么 |
|---|---|---|---|---|
| `KouriChat/KouriChat` | 3,259 ★ | Python | 自定义 | 基于大模型的"更逼真的情感陪伴程序"，接入第三方聊天平台（**明确写着禁止接入微信、QQ 等腾讯系**） |
| `Synthintel0/MyGirlGPT` | 437 ★ | Python | 无 | 在你自己服务器上用本地模型跑的 AI 女友 |
| `momori777/Artemis` | 354 ★ | Python | 自定义 | 本地全离线 AI 女友：语音克隆 + 出图 + Live2D + 记忆库，QQ 和 Telegram 双通道 |
| `AnnenkovLabs/girl-agent` | 345 ★ | TypeScript | 自定义 | **"不是聊天机器人，是有状态的角色"**——有睡眠、心情、日程、记忆、关系阶段和吵架 |

**这一路的共同点**：不自己做 App，而是把自己塞进你每天都在用的聊天软件里。好处是零安装成本、天然有"她给你发消息"的推送感。Artemis 和 girl-agent 的可贵之处在于点出了**两个真正的命门：长期记忆**（Artemis 用 mem0 + 向量库）和**关系状态机**（girl-agent 的睡眠/心情/关系阶段）。

⚠️ **合规红线**：KouriChat 在简介里亲自写明"禁止接入微信、QQ 等腾讯系软件"。这不是谦虚，是这类项目在国内的法律现实——寄生大平台随时会被封。

### 第 4 路：零件供应商 —— 不卖整机，卖零件

| 项目 | 星数 | 语言 | 许可证 | 它是什么 |
|---|---|---|---|---|
| `mem0ai/mem0` | 65,946 ★ | Python | Apache-2.0 | 专门给 AI 做"长期记忆"的模块——让她记住你说过的话 |
| `RVC-Boss/GPT-SoVITS` | 62,108 ★ | Python | MIT | 用 1 分钟录音就能克隆出一个声音来做语音合成 |

**注意这两个的星数比所有"整机"项目都高**。这说明真正的技术门槛不在"拼一个聊天界面"，而在"**记住一个人**"和"**说话像真人**"这两件事上。谁掌握了记忆和声音，谁就掌握了这个品类的核心竞争力。

## 二、不管走哪条路，机器都由这七块拼成

把"人机恋 App"拆开看，它其实就是一个能听、能记、能想、能说、有脸的机器：

| # | 零件 | 大白话 | 干什么的 | 开源参考 |
|---|---|---|---|---|
| 1 | **人设卡** | 她的"人物设定书" | 性格、说话习惯、背景故事、开场白。决定"她是谁" | SillyTavern 角色卡格式 |
| 2 | **耳朵**（语音识别） | 听懂你说话 | 把你说的语音变成文字。纯文字聊天时不需要 | Whisper 系 |
| 3 | **记性**（记忆系统） | 她记得你 | 短期：刚才聊了什么；长期：你的生日、你怕什么、上次为什么吵架 | mem0 + 向量库 |
| 4 | **大脑**（大模型） | 她想说什么 | 结合人设 + 记忆 + 当前这句话，生成回复 | 云端 API 或自建开源模型 |
| 5 | **状态机** | 她的心情和作息 | 她今天累不累、心情好不好、你们到哪一步了。让回复不只是"接话"而是"有态度" | girl-agent 的思路 |
| 6 | **嗓子**（语音合成） | 她的声音 | 把文字变成声音。想有专属声音就用声音克隆 | GPT-SoVITS |
| 7 | **脸 / 身体** | 她的样子 | 一张会动的立绘（Live2D），或者干脆纯文字 | Open-LLM-VTuber、airi |

**七块的难度排序**（从难到易）：记忆 > 状态机 > 声音克隆 > 大模型接入 > 立绘 > 语音识别 > 界面。

**最值钱的两块是记住你和她有脾气**——这也正是市面上"付费 AI 女友"和"开源玩具"拉开差距的地方。界面和立绘是最容易被抄的。

## 三、一次对话的完整旅程

```
你说一句话 → 她是这样处理的

┌──────────┐
│ 你输入   │  打字 或 说语音
└────┬─────┘
     ↓
┌──────────────────┐
│ 1. 耳朵（可选）  │  语音 → 文字
└────┬─────────────┘
     ↓
┌──────────────────────────────────────┐
│ 2. 组装"这一刻的她"                  │
│   = 人设卡（她是谁）                 │
│   + 短期记忆（刚才聊了什么）         │
│   + 长期记忆（你生日/她记得的事）    │
│   + 当前状态（她现在心情/几点/关系） │
└────┬─────────────────────────────────┘
     ↓
┌──────────────────┐
│ 3. 大脑（大模型）│  想出一句回复
└────┬─────────────┘
     ↓
┌──────────────────────────────┐
│ 4. 输出加工（按需）          │
│   嗓子：配她的声音           │
│   脸：切换表情/动作          │
└────┬─────────────────────────┘
     ↓
┌──────────────────┐
│ 5. 呈现给你      │  文字气泡 / 语音 / 会动的立绘
└────┬─────────────┘
     ↓
┌──────────────────────────────┐
│ 6. 回写记忆（悄悄进行）      │
│   把这次对话里值得记住的事   │
│   存进她的长期档案           │
└──────────────────────────────┘
```

**关键认知**：第 6 步（回写记忆）是最容易被忽略、但最决定成败的一步。没有它，聊到第 100 天她还是第一天认识你——那就不叫恋爱，叫自言自语。

## 四、三种可选的"整机形态"

| | A. 手机 App（云端大脑） | B. 桌面伴侣（本地大脑） | C. 聊天软件机器人 |
|---|---|---|---|
| **用户要装什么** | 应用商店下一个 App | 一台带显卡的电脑 + 一堆环境 | 什么都不装 |
| **她住哪** | 你的服务器 | 用户自己的电脑 | 微信/QQ/Telegram |
| **谁掏算力钱** | 你（所以通常要收费） | 用户（所以免费） | 你或用户 |
| **能有什么脸** | 立绘/动画 | Live2D / 3D 全套 | 只有头像 |
| **推送"想你"** | 有（系统推送） | 弱 | 最强（原生消息感） |
| **开源参考** | 几乎没有成熟项目 | airi / Open-LLM-VTuber | KouriChat / girl-agent |
| **合规风险** | 中（内容审核、备案） | 低（用户自己机器） | **高**（寄生平台随时封号） |
| **上手难度** | 中 | 极高 | 低 |

**一个真实发现**：我按 "AI girlfriend + flutter/android/ios" 搜，807 个结果里**没有一个成熟的移动原生 AI 伴侣项目**——排前面的全是桌宠和 IM 机器人。这条信息很重要：**如果你要做手机 App，开源世界里能直接抄的整机几乎没有，你得自己攒**。好消息是零件（mem0、GPT-SoVITS）都很成熟，攒的难度主要在组装。

## 五、我的推荐

**主线建议：走 A 路（手机 App）的轻形态，把资源全押在"记住你"和"她有脾气"上，形象先用立绘不做 3D。**

理由三条：

1. **手机 App 决定了大脑必须在云上**。普通用户不会为谈恋爱装显卡。所以形态一旦选 App，大模型就只能调云端（第三方 API 或自建服务端），这一点没得选。
2. **人机恋的命门是"她记得我"，不是"她长得美"**。mem0 六万五千星、GPT-SoVITS 六万二千星，而所有整机项目都没到这个量级——市场用脚投票告诉你钱在哪。立绘和界面是天花板最低的部分，先做到"能看"，别做到"惊艳"。
3. **关系状态机是被严重低估的差异点**。girl-agent 的思路（睡眠、心情、关系阶段、会吵架）只有 345 星，但它是唯一一个在简介里喊出"这不是聊天机器人，是有状态的角色"的项目。这是当前赛道的空白地带。

**建议的零件选型（都可商用）**：
- 人设卡：兼容 SillyTavern 角色卡格式（白捡几千张现成人设）
- 记忆：mem0（Apache-2.0，可商用）
- 声音：GPT-SoVITS（MIT，可商用）——但放二期，因为要服务器算力
- 立绘：Live2D（别上 3D，成本和收益不成正比）
- 大模型：先接第三方 API 跑通，验证完再考虑自建

⚠️ **许可证坑**：SillyTavern 是 **AGPL-3.0**——如果你直接抄它的代码并做成联网服务，法律上要求你把自己的服务端代码也开源。**只能学它的"角色卡格式"（格式不受版权保护），不能抄它的代码**。airi（MIT）、GPT-SoVITS（MIT）、mem0（Apache-2.0）这三家可以放心借鉴。

## 六、需要你拍板的四件事

1. **做成什么形态？** —— 手机 App / 桌面软件 / 寄生聊天软件 / 先做个网页版试试水
2. **要不要"身体"？** —— 纯文字 / 加语音 / 加会动的立绘 / 全套 3D（成本差一个数量级）
3. **给谁用？** —— 只给你自己玩（那可以上本地、不花钱）/ 给很多人用（那必须有服务器、账号、付费）
4. **记忆做到哪一步？** —— 只记当前对话 / 长期档案（记住你的喜好和经历）/ 会主动关心你（定期发消息问你今天怎么样）

第 4 条是"人机恋"和"聊天机器人"的分水岭，建议至少做到第二档。

## 七、还没查的（诚实声明）

- 本文**没有 clone 任何项目读源码**，所有"它内部怎么实现"都属于基于官方简介的推断。
- 各项目的**实际代码质量、活跃度、issue 里的坑**未评估——如果你的方向定了，下一步应该挑 1-2 个最接近的项目（大概率是 airi 和 Artemis）真正读一遍源码再定架构。
- **国内合规环境**（App 上架、内容审核、AI 备案）未调研，但这是手机 App 路线绕不开的一道关，建议方向定了立刻单独评估。
