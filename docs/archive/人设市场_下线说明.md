### ⚠️ 三张表**保留，没有 DROP**

`market_personas` / `market_likes` / `market_comments` 仍在库里，`_migrate_market_columns`
的调用也保留（幂等、无害）。

**理由**：删功能 ≠ 删数据。留着表是**可逆**的 —— 将来反悔或要做数据分析，
数据还在；DROP 了就真没了。表不占什么资源，也不构成攻击面（没有路由碰它）。

## 三、**保留下来的技术**（这才是重点）

被删的是"市场这个功能"，不是"图片这套能力"。以下**全部保留**并已去掉 `_mkt_` 前缀，
新头像链路直接复用：

| 保留物 | 位置 | 为什么值钱 |
|---|---|---|
| 三档 WebP 压缩 | `backend/main.py` 的 `_write_webp_variants` / `_encode_bounded` / `_fit_long_side` | 300 KB/s 出口带不动原图；三档是列表能用的前提 |
| 变体路径派生 + 存在性回落 | `_variant_url` / `_upload_exists` | 老图不 500 |
| 通用图片上传 | `POST /api/v1/upload/image` | 头像上传复用 |
| `/uploads/` 长缓存 | `no_cache_static` 中间件里的 uploads 分支 | 内容哈希命名 → `immutable` 安全 |
| 客户端图片加载 | `ui/components/RemoteImage.kt` | 独立 OkHttp + 200MB 磁盘缓存 |
| 本地图片存取 | `data/ImageStore.kt` | 头像本地缓存复用 |

**完整经验见** `memory/图片三档与缓存_经验_v1.md`（实测数字、解压炸弹、
"同步压图冻结事件循环"那条教训、缓存头只给 200 等）。
