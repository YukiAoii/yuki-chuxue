## 一、一句话

后端跑在 `127.0.0.1:11446`，由 Nginx 的 **`https://sy.example.com:11445`** 收口对外
（⚠️ 没有 `/yuki` 前缀 —— 见文首「部署形态已变更」）。
**它是可选增强** —— 它挂了，App 的聊天、记忆、人设、头像一律照常。

它只提供四件本地做不到的事：

| 能力 | 说明 |
|---|---|
| **管理后台** | 网页仪表盘 + 设备数据 + 用户 + 邮件配置 + 公告 + 操作日志 |
| **使用统计** | App 上报的计数（会话数/消息数/token），后台仪表盘的数据源 |
| **公告** | 你在后台发，App 拉取 |
| **账号** | 邮箱验证码登录（**换设备时**把资料带走；不注册也能用全部本地功能） |

## 二、开起来

### 启动

双击：`项目1\Yuki初雪\backend\start_backend.bat`

它会自己找 Python、缺依赖就装（清华镜像）、然后启动。

### ⚠️ 首次启动会打印**管理员密码**

```
==================================================================
  Yuki 初雪 - 后端已启动
  监听：   http://127.0.0.1:11445
  数据库： ...\backend\data\yuki.db
------------------------------------------------------------------
  [!] 首次启动，已创建管理员账号（请立即记下并妥善保存）：
      用户名：admin
      密  码：xxxxxxxxxxxx
  这个密码只显示这一次；忘了只能改库或删 data/yuki.db 重建。
------------------------------------------------------------------
```

**这个密码只显示这一次。** 关掉窗口就再也拿不到了（密码只存哈希，我也没法还原）。
忘了的话：停掉后端 → 删 `backend\data\yuki.db` → 重新启动 → 会生成新密码
（代价是后台的历史统计数据一并清空；App 端数据**不受影响**，它根本不在这个库里）。

### 访问

| 入口 | 地址 |
|---|---|
| 管理后台 | `https://sy.example.com:11445/` |
| 健康检查 | `https://sy.example.com:11445/health` |

### 停止

关掉那个命令行窗口即可（或在窗口里按 `Ctrl+C`）。

### 自检（改完配置后建议跑一次）

```bat
cd 项目1\Yuki初雪\backend
py -3 test_backend.py                              :: 纯函数与 DB，24 项
py -3 e2e_check.py http://127.0.0.1:11445 你的密码   :: 真发 HTTP，74 项
```

第二个是端到端自检：它会真的登录、上报一台假设备、发公告、改设置，然后**把痕迹清掉**。
它跑通，说明整条链路是活的。

## 三、Nginx（已经配好了）

配置在 `C:\nginx\conf\nginx.conf`，后端那一段是（2026-10-01 实测，逐字）：

```nginx
server {
    listen       11445 ssl;
    server_name  sy.example.com;

    ssl_certificate      C:/cert/sy.example.com-chain.pem;
    ssl_certificate_key  C:/cert/sy.example.com-key.pem;
    # …TLS 参数、client_max_body_size 32m…

    location / {
        proxy_pass http://127.0.0.1:11446;      # 后端内部端口 11446
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;                 # 「测试发信」要等 SMTP 握手
        proxy_send_timeout 120s;
    }
}
```

**要点**：`location` 是 `/`、`proxy_pass` 末尾**不带斜杠** ——
所以后端看到的路径就是原样的 `/`、`/admin.css`、`/api/...`，没有前缀要剥。
（旧版文档写的 `location /yuki/` + `proxy_pass .../` 那套**已经不用了**。）

改动配置后：

```bat
C:\nginx\nginx.exe -t -c C:\nginx\conf\nginx.conf      :: 先验证语法
C:\nginx\nginx.exe -s reload -c C:\nginx\conf\nginx.conf   :: 再平滑重载
```

## 四、邮件服务（在后台里填，不用改代码）

进后台 → 左侧「**邮件服务**」→ 填 SMTP → 保存 → 点「发送测试」验证。

保存后**立即生效**，不需要重启后端。

### 常见邮箱的参数

| 邮箱 | SMTP 服务器 | 端口 | 加密 | 密码填什么 |
|---|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | SSL | **授权码**（在 QQ 邮箱设置里生成，不是登录密码） |
| 163 邮箱 | `smtp.163.com` | 465 | SSL | 授权码 |
| Gmail | `smtp.gmail.com` | 465 | SSL | 应用专用密码 |
| 阿里云邮 | `smtp.mxhichina.com` | 465 | SSL | 邮箱密码 |

⚠️ 绝大多数国内邮箱都要用**授权码**而不是登录密码 —— 填错的表现是"SMTP 认证失败"，
后台会把这句话原样显示出来（不会吞掉）。

### 邮件没配好会怎样

**不会卡死。** 注册验证码仍然会生成，并且显示在后台「邮件服务」页的
**「待用验证码」**里 —— 你在那里读到码，自己在 App 里输入即可完成注册。
（这条降级通道是刻意做的：另一个项目踩过"邮件服务未配置 → 注册死锁"的坑。）

## 五、后台那些数字从哪来

```
App 启动 ──(4 秒后)──► POST /api/app/report ──► devices 表 ──► 仪表盘
         （只在设置里填了"后端地址"且开关打开时）
```

### 所以要用统计，得先在 App 里做两件事

1. 设置 → **我的服务器** → 「后端地址」填 `https://sy.example.com/yuki`
2. 同页确认「上报使用统计」是开的（默认开）

### 上报了什么（**完整清单**）

```
device_id        随机生成的本机标识（不是 Android ID，也不是手机号）
model            机型（如 "Pixel 8"）
android_version  Android 版本
app_version      App 版本
persona_count    人设数量
session_count    会话数量
message_count    消息数量
memory_count     记忆条数
hit_tokens       缓存命中 token
miss_tokens      缓存未命中 token
```

**只有计数与系统属性 —— 没有任何对话内容、人设文本、记忆内容，也没有 API Key。**
`TelemetryTest` 里有一条断言专门守这件事：一旦有人往上报体里加"标题/内容"这类字段，
测试会红。

留空「后端地址」= **一个字节都不会发往自建服务**。

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 打开 `https://sy.example.com:11445/` 显示 **502** | 后端没跑。双击 `start_backend.bat` |
| 打开 `https://sy.example.com/`（**443**，根）显示 502 | **正常** —— 443 是另一个项目的站点，它的后端没启动。与本后端（11445/11446）无关 |
| 后台能进，但仪表盘全是 0 | App 还没上报过。按上面第五节在 App 里填地址 |
| 邮件一直发不出去 | 「邮件服务」页点「发送测试」看具体报错；国内邮箱八成是**授权码**没填对 |
| 忘了管理员密码 | 停后端 → 删 `backend\data\yuki.db` → 重启（后台统计会清空，App 数据不受影响） |
| 端口 11445 被占用 | `netstat -ano \| findstr :11445` 拿到 PID，再 `taskkill /PID <pid> /F`。**不要**用 `Get-Process python \| Stop-Process` —— 那会把别的项目的 Python 服务一起杀掉 |
| 后台中文乱码 | `start_backend.bat` 是 UTF-8 且开头有 `chcp 65001`，两者必须匹配。别单独改其中一个 |

## 八、安全说明（当前形态的边界）

| 项 | 现状 |
|---|---|
| 管理员密码 | PBKDF2-HMAC-SHA256（12 万次迭代），只存哈希；令牌同样只存哈希 |
| 传输 | 全程 HTTPS（Nginx 用你的证书） |
| 后端暴露面 | **只监听 127.0.0.1** —— 外网进不来，必须经 Nginx |
| 客户端上报 | 无需令牌（不注册的用户也要能上报）；代价是**任何人都能往 devices 表写数据**。自用可以接受：最坏情况是仪表盘数字偏大，不影响任何功能 |
| 数据库 | SQLite，文件在 `backend\data\yuki.db`（WAL 模式） |
| 备份 | **没有做自动备份**。要备份就复制那个 `.db` 文件（连同 `-wal`） |
| 与 App 的关系 | 这个后端**拿不到**你的对话内容、人设、记忆 —— 它们全在手机上，从不上传 |

> 后面若要做"跨设备同步"，那必须**先**把端到端加密落地（见 `后端与我的页设计_v1.0.md`
> 的「三条主张」）—— 聊天记录不能以可读形态存在服务器上。

## 九、目录结构

```
项目1\Yuki初雪\backend\
├── main.py               后端全部逻辑（单文件，约 3200 行）
├── requirements.txt      只有 fastapi + uvicorn
├── start_backend.bat     双击即启动
├── test_backend.py       纯函数与 DB 层测试（24 项）
├── e2e_check.py          端到端 HTTP 自检（74 项，不留痕）
├── static\               管理后台前端（原生 HTML/CSS/JS，零构建）
│   ├── index.html
│   ├── admin.css
│   └── admin.js
└── data\
    └── yuki.db           SQLite 数据库（启动后自动生成）
```

**改后台前端不用重新构建** —— 改完 `static/` 里的文件，浏览器刷新即可。
（这也是选原生而不是 React/Vue 的原因：这台机器就是服务器，多一条构建链不划算。）
